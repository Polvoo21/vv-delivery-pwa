# Запуск оплаты через ЮKassa

## Что уже делает приложение

- Создаёт платежи только на сервере через `POST https://api.yookassa.ru/v3/payments`.
- Использует HTTP Basic Auth: `YOOKASSA_SHOP_ID` как логин и `YOOKASSA_SECRET_KEY` как пароль.
- Передаёт уникальный `Idempotence-Key` для платежей и возвратов.
- Отправляет гостя на защищённую redirect-страницу ЮKassa.
- Не считает возврат браузера подтверждением оплаты: статус повторно запрашивается у ЮKassa.
- Обрабатывает `payment.succeeded` и `payment.canceled` через один webhook.
- Передаёт заказ на кухню и подтверждает запись на мастер-класс только после статуса `succeeded`.
- Проверяет сумму заказа по серверному каталогу, а сумму мастер-класса — по серверному событию.
- Поддерживает повторную попытку после отменённого платежа и полный/частичный возврат заказа из админки.

## Переменные окружения

Добавить в серверный `.env`:

```dotenv
PUBLIC_SITE_URL=https://vmestevkusnee.ru
YOOKASSA_MODE=production
YOOKASSA_SHOP_ID=<идентификатор магазина из Настройки → Магазин>
YOOKASSA_SECRET_KEY=<секретный ключ из Интеграция → Ключи API>
YOOKASSA_RECEIPT_ENABLED=0
YOOKASSA_VAT_CODE=
YOOKASSA_SAVE_PAYMENT_METHOD_ENABLED=0
```

Секретный ключ нельзя добавлять в git, клиентский JavaScript, скриншоты, логи или переписку. Файл `.env` уже исключён из git.

Для запуска нужны **два значения**: `shopId` и секретный API-ключ. `YOOKASSA_MODE` используется приложением как эксплуатационная метка; реальный или тестовый контур ЮKassa определяется самим магазином и его ключами.

## Чеки и 54-ФЗ

Перед первым реальным платежом нужно узнать, какой сценарий фискализации включён в договоре и личном кабинете ЮKassa.

- Если данные для чека нужно передавать вместе с платежом, установить `YOOKASSA_RECEIPT_ENABLED=1`.
- Указать согласованный с бухгалтером/кассой `YOOKASSA_VAT_CODE` от 1 до 12.
- Не угадывать ставку НДС. Ошибка может привести к неверному чеку или отклонению платежа.
- Заказ использует предмет расчёта `commodity`, мастер-класс — `service`.
- При включённых чеках сайт передаёт email гостя; для мастер-класса email обязателен.

## Настройка webhook в личном кабинете

URL:

```text
https://vmestevkusnee.ru/api/payments/yookassa/webhook
```

Подписать URL минимум на события:

- `payment.succeeded`
- `payment.canceled`
- `refund.succeeded`

Приложение не доверяет телу уведомления как окончательному источнику: оно получает платеж заново через API, сверяет UUID объекта, сумму и валюту.

## Проверка ключа

После добавления значений в локальный или серверный `.env`:

```bash
npm run payments:check
```

Команда обращается к `GET /v3/me`, не выводит секрет и показывает статус магазина и доступную информацию о фискализации.

## Утренний порядок запуска

1. Выпустить и сохранить секретный ключ в менеджере паролей.
2. Вписать `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в серверный `.env`.
3. Уточнить фискализацию и только после этого заполнить `YOOKASSA_RECEIPT_ENABLED` и `YOOKASSA_VAT_CODE`.
4. Выполнить `npm run payments:check`.
5. В личном кабинете ЮKassa сохранить webhook URL и события.
6. Собрать и запустить приложение по обычному серверному процессу.
7. Открыть `/api/payments/yookassa/config`: ожидается `configured: true`, `mode: production`.
8. Провести один минимальный реальный заказ и проверить: переход в ЮKassa, возврат на сайт, статус `Оплачено`, появление заказа в админке и webhook в истории ЮKassa.
9. Провести тест мастер-класса на актуальном открытом событии, когда оно добавлено в `shared/masterclass-events.js`.
10. Проверить чек в личном кабинете/ОФД, если фискализация включена.

## Если платеж завис или отменён

- `pending`: не создавать новый заказ сразу; повторно проверить статус или открыть сохранённую ссылку.
- `canceled`: кнопка оплаты создаст новую операцию с новым ключом идемпотентности.
- HTTP 500/сетевая ошибка при создании: повторить тот же запрос; приложение использует тот же ключ идемпотентности для незавершённой попытки.
- Заказ не передаётся на кухню, пока сервер ЮKassa не вернул `succeeded`.
