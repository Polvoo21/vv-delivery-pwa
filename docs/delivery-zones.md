# Зоны доставки

## Единый источник

Актуальная карта зон доставки хранится в одном файле:

```text
public/assets/site/delivery-zones.geojson
```

Этот JSON используется везде:

- модалка выбора адреса при оформлении заказа;
- публичная страница `/delivery-zones`;
- локальная страница `/dev/delivery-zones`.

Если нужно обновить зоны, заменяем только этот файл. После деплоя сайт подхватит новые контуры на всех картах.

## Формат файла

Файл должен быть валидным GeoJSON:

```json
{
  "type": "FeatureCollection",
  "metadata": {
    "name": "Зоны доставки Вместе Вкуснее",
    "updatedAt": "07.07.2026"
  },
  "features": []
}
```

Поддерживаются геометрии:

- `Polygon`;
- `MultiPolygon`.

Координаты в GeoJSON должны быть в порядке:

```text
[долгота, широта]
```

Для Чебоксар это выглядит примерно так:

```text
[47.25, 56.14]
```

## Свойства зоны

Для каждой зоны можно указать:

```json
{
  "properties": {
    "name": "Центр",
    "description": "Зона бесплатной доставки",
    "fill": "#ca7767",
    "fill-opacity": 0.22,
    "stroke": "#ca7767",
    "stroke-width": "2",
    "stroke-opacity": 0.9
  }
}
```

`name` или `description` показываются на публичной странице и в tooltip на карте.

## Кэширование

`service-worker.js` настроен так, чтобы `/assets/site/delivery-zones.geojson` запрашивался из сети без сохранения в runtime cache. Дополнительно фронтенд добавляет параметр времени к запросу. Это сделано специально, чтобы новая карта зон не застревала у гостей в старом кэше.

## Проверка после замены

1. Открыть `/delivery-zones`.
2. Проверить, что контуры на карте изменились.
3. Открыть оформление заказа и выбрать адрес на карте.
4. Проверить, что адрес внутри новой зоны разрешает доставку, а адрес вне зоны блокирует доставку.
5. Запустить `npm run build` локально перед деплоем.
