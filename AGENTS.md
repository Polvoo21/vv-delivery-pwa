# AGENTS.md

## Project

Проект: Семейная пиццерия «Вместе вкуснее».

Домен и маршруты:

- `vmestevkusnee.ru` - основной сайт ресторана, меню, доставка, самовывоз, документы и контакты.
- `/checkout` - оформление заказа на основном сайте.
- `/payment` - переход к онлайн-оплате.
- `/admin` - единая админка; интерфейс зависит от роли аккаунта: руководитель или администратор.
- Партнерский кабинет и промокоды не выносить в отдельный визуальный продукт без отдельного решения.

Проект работает на личном VPS. Заказы обрабатываются на сайте и в админке; внешние уведомления в сторонние чаты не являются основным каналом. Не ломать рабочую логику сохранения и обработки заказов без отдельного решения. Не выполнять серверные действия без явного разрешения: ssh, scp/rsync, docker compose up/down, pm2 restart, systemctl restart, nginx reload, git pull на сервере.

## Main working rule

Для обычных правок сначала читать только файлы, которые реально участвуют в задаче.

Дизайн-документы и skills подключать точечно:

1. `docs/design/MASTER.md` и `docs/design/page-briefs.md` - когда меняется направление страницы, секции или дизайн-системы, а не при микрофиксе.
2. `ui-ux-pro-max` - только по явной просьбе пользователя или для крупного UI-аудита/редизайна.
3. `vv-food-redesign` - только по явной просьбе пользователя или для крупного этапа редизайна/QA.
4. Для мелких CSS/JS правок не поднимать большие skills и не читать все design docs.

Не делать большой редизайн за один проход. Работать этапами и показывать diff.

## Brand direction

Главный визуальный ориентир: строгий, чистый, лаконичный food-commerce уровня Dodo по зрелости UX, но без копирования чужого кода, ассетов, текстов, логотипов, фирменных иллюстраций и точной раскладки.

Важно: если пользователь просит “как Dodo” или “в стиле Dodo”, это означает UX-зрелость, плотность, чистоту, сетку, ритм, ясные CTA и понятные флоу. Dodo-оранжевый и его производные не переносить. Все оранжевые акценты референса заменять на фирменный красно-розовый акцент «Вместе Вкуснее» (`--vv-orange`, сейчас `#ca7767`) и его мягкие производные. Не заменять его зеленым.

Больше не возвращаться к старому "теплому декоративному" направлению: без бежевых, кремовых, песочных и теплых лендингов, случайных плашек, декоративных наклеек, орбов, размытий, glassmorphism и градиентных фонов.

Базовые поверхности всегда Dodo-like: белый фон, светло-серый фон `#f3f4f6`/`#f7f8fa`, темный текст, фирменный красно-розовый CTA. Бежевый/кремовый не использовать даже как мягкую подложку.

Ощущение бренда: современная сильная доставка и ресторан с понятным меню, белыми/светло-серыми поверхностями, плотной сеткой, аккуратной типографикой, крупными фото еды и фирменным красно-розовым акцентом только там, где есть действие.

Копирайтинг: коротко, уверенно, по-человечески, без канцелярита, без длинных тире, без рекламной воды и без ИИ-интонации.

## Visual quality rules

Обязательно:

- Единая дизайн-система: цвета, типографика, отступы, радиусы, тени, motion.
- Основной стиль: белый фон, светло-серые блоки, черный/темно-серый текст, фирменный красно-розовый action-color, компактные карточки, строгая сетка.
- Все публичные страницы сайта используют общую шапку `SiteHeader` как на главной, включая compact-состояние после скролла и меню. Кнопка "назад" или "вернуться" может быть только дополнительным элементом внутри контента, а не заменой шапки.
- Hero и секции делать лаконично: крупный реальный food visual, сильный заголовок, понятные CTA, минимум декоративных элементов.
- Каталог доставки должен быть уровня современного food delivery: sticky категории, понятные карточки, быстрые CTA, корзина, адрес, самовывоз.
- Админка должна выглядеть как рабочий инструмент ресторана, а не темная тестовая заглушка.
- Партнерский кабинет должен быть строгим, понятным и доверительным: промокод, заказы, начисления, комиссия, статусы.

Запрещено:

- Копировать код, CSS, ассеты, тексты, логотипы и фирменные иллюстрации Dodo.
- Смешивать 5 разных стилей на одной странице.
- Использовать случайные emoji вместо SVG-иконок.
- Использовать бежевые, кремовые, песочные, tan/cream/ivory-поверхности как направление интерфейса.
- Добавлять новые градиенты любого типа: `linear-gradient`, `radial-gradient`, `conic-gradient`. Существующие градиенты при касании экранов заменять на плоские цвета, реальные фото и аккуратные тени.
- Делать glassmorphism, неон, декоративные орбы, bokeh, тяжелые blur-слои, кислотные акценты, чрезмерные тени.
- Возвращать старое направление с "теплой семейной итальянской" декоративностью как визуальный стиль. Семейность остается в смыслах и контенте, но не в оформлении.
- Добавлять новые production-зависимости без необходимости.
- Делать деплой, перезапуск процессов или изменения на VPS без локальной проверки, просмотра результата и явного разрешения владельца проекта.

## Implementation rules

- Вынести дизайн-токены в один источник: CSS variables, Tailwind theme или tokens-файл, в зависимости от текущего стека.
- Компоненты: `Button`, `Card`, `Badge`, `Header`, `ProductCard`, `CategoryTabs`, `CartDrawer`, `AddressSheet`, `OrderStatusPill`, `MetricCard`.
- Все кликабельное имеет hover, active, focus-visible.
- Motion: 150-240 ms для hover/press, 250-360 ms для drawer/modal/sheet. Уважать `prefers-reduced-motion`.
- Responsive acceptance: 375, 390, 768, 1024, 1440 px.
- Доступность: контраст текста минимум WCAG AA, видимые focus states, кнопки не меньше 44 px по высоте на mobile.

## Quality gate before final answer

Перед сдачей проверить:

- `npm run lint`, если есть.
- `npm run build`, если есть.
- Локальный preview без runtime ошибок.
- Для VPS: подготовлены команды деплоя или чеклист, но не выполнены без отдельного разрешения.
- Локальная визуальная проверка ключевых страниц; скриншоты делать только по отдельной просьбе.
- Не сломана логика заказа, сохранение в базе и обработка в админке.
- Нет копипаста из Dodo.
